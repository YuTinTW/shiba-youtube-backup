# 柴犬存檔室：後續開發步驟

更新日期：2026-11-15。接手對象：Argon。狀態：以下 10 步均尚未在本次任務執行。

先讀 [交接現況](ARGON_HANDOFF.md) 與 [安全政策](../SECURITY.md)。本文件是後續開發計畫，所有實作選擇均為建議；具體修改應依重新檢查的證據決定，不代表已證實漏洞。本次只撰寫文件，不啟動開發。

## 執行方式與工作邊界

目標先達到「本機可靠下載且不破壞既有檔案」，再達到「可供其他使用者安裝的獨立成品」。既有三欄介面與功能範圍維持為開發基準；播放清單、MP3 等新增功能先不列入這輪計畫。

順序原則為 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10。07 的介面觀察可在 01 先做，正式整體驗收須使用修正後版本。某步驟遇到環境或外部服務阻擋時，記錄原因，繼續其他不依賴該阻擋的工作；相關完成條件仍維持未通過。

每步先重現問題或確認缺口，再做最小變更，執行直接相關的安全測試與必要回歸測試。本文提到的新增模組與測試檔是候選位置；能在現有檔案清楚完成就不必拆檔。不得為了照計畫而重寫整個專案。

只操作已授權專案，跨專案存取、高風險操作及對外發佈依明確授權執行。不要刪除目前使用的 `.runtime-packages/`、替換系統 Python 或全域套件，也不要在使用者真實下載目錄做破壞性驗證。沒有 Git 儲存庫時先建立檔案雜湊基準；本計畫不要求自動初始化 Git。

每步在專案內 `docs/verification/` 留下適量且已遮蔽敏感資料的開發驗收紀錄，包含：日期、工作編號、環境與檔案版本、實際改動、執行命令、預期／實際結果、通過／失敗／跳過、阻擋及下一步。若正式使用 Codex Security 掃描，掃描產物須遵循該技能的管理儲存規則，不用一般開發紀錄取代。

## 01．建立環境與測試基準

**檢查位置：** `README.md`、啟動腳本、`requirements.txt`、`tests/`、目前 Python 與工具路徑。初始階段不改下載邏輯。

1. 確認工作根目錄與 `SECURITY.md`，保存現有程式與設定的 SHA-256，避免覆蓋接手前的修改。
2. 記錄 macOS、CPU 架構、Python 執行檔、Tk 版本、yt-dlp／EJS 實際版本與匯入位置、FFmpeg／ffprobe／Deno 路徑與版本。版本應由實際選用環境取得，不照抄 README。
3. 用能符合專案需求的 Python 執行 `python3 -B -m unittest discover -s tests -v`；實際命令須換成選定解譯器，記錄完整路徑。現有 18 個測試方法是起始盤點，後續新增後總數會改變。
4. 若遇到缺模組或 Tk 阻擋，先辨識原因；必要時在專案內建立獨立開發環境，不覆寫現有 runtime。需要選新版本時，先查官方相容性與來源，不假定 requirements 已驗證。
5. 嘗試 GUI 基本啟動並記錄；無法使用圖形介面時標示阻擋，不以 import 成功替代視窗啟動。

**完成條件：** 有可追溯的環境與測試基準，每個失敗或跳過都有原因；可以判斷後續失敗是原有問題或新變更造成。不得宣稱本步已完成真實下載驗證。

## 02．先完成檔案保全與清理驗證

**候選修改位置：** `core.py` 的 `check_folder()`、`safe_name()`、`publish_file()`、`download()`；`tests/test_core.py`、`tests/test_pipeline.py`，必要時新增 `tests/test_file_safety.py`。

1. 在測試專用目錄建立既有檔案與資料夾，記錄其內容雜湊與存在性，作為每項失敗測試前後的比較依據。
2. 測試一般同名、同名序號已存在、無硬連結支援、複製中途失敗、權限錯誤、磁碟錯誤，以及清理時的例外。
3. 以可重現的同步點模擬符號連結、目錄或目標路徑被替換；不要依賴任意 sleep 碰運氣重現競態。
4. 優先確認 `publish_file()` 複製失敗後 `unlink()` 的對象是否仍屬本次建立項目，再選擇合適的安全發佈與清理方式。僅做一次路徑比較不能當成解決所有競態的證據。
5. 對下載來源、音訊、合併輸出及發佈目標確認路徑邊界；不可信中繼資料不得決定工作範圍外的讀寫。
6. 讓合併與驗證失敗後不發佈無效結果；遇到清理不確定時不得冒險刪除既有檔案，需回報受限範圍的殘留。
7. 區分一般例外、可處理中斷與不可攔截的強制終止；強制終止可能留下暫存資料，不應承諾所有終止都能立即清理。

**必要測試：** 硬連結及替代複製兩路徑、既有檔案與符號連結、複製失敗清理、並行同名、合併失敗、有效輸出與部分成功。不同檔案系統無法實測時，替身測試與實機缺口分開列出。

**完成條件：** 測試中的既有檔案前後不變；失敗、清理及競態不刪改非本次項目；回歸測試可穩定重現原問題並驗證修正。尚未驗證的檔案系統不能列為已支援。

## 03．明確化外部工具、匯入與工作程序邊界

**候選修改位置：** `core.py` 的 `tool()`、`run_process()`、`ydl_options()`，`app.py`、`gui.py` 的工作程序讀寫，以及啟動腳本。必要時新增 `tests/test_worker.py`／`tests/test_tools.py`。

1. 列清原始碼與封裝模式允許的工具來源，確認工具為預期可執行檔；封裝模式缺工具須失敗，不回落開發機 PATH。
2. 檢查啟動與子程序繼承的 PYTHONPATH、PATH 及 Python 環境；避免非預期套件或工具優先載入，同時保留必要的 TLS、系統與執行設定。
3. 維持參數陣列；測試空白、中文、引號與以連字號開頭的路徑，確認不被解讀成非預期選項。不為方便改用 shell 字串拼接。
4. 驗證 worker 請求的 action、url、folder、selected 型別與合理長度；錯誤、空輸入、非 JSON 或未知動作應回報受控錯誤。
5. 驗證 GUI 接收事件的型別、必要欄位與未知事件處理，避免不完整事件使輪詢永久停止或介面鎖死。

**必要測試：** 工具缺少、錯誤來源、非零回傳、逾時、惡意參數文字、錯誤工作請求、異常工作事件及程序提前結束。工具測試使用可控替身，不執行未知二進位。

**完成條件：** 來源與參數規則明確，失敗會停止相關工作並恢復介面；畸形請求或事件不造成任意操作。背景程序仍不能宣稱為權限沙箱。

## 04．改善更新切換、恢復與可追溯性

**候選修改位置：** `更新下載元件.command`、`requirements.txt`；必要時將更新邏輯移至可測試的專案內模組，搭配 `tests/test_updater.py`。

1. 先記錄目前版本來源與備份流程；選擇適合日常使用的版本策略。建議一般更新採經測試的明確版本與依賴集合，預發佈版本須有明確選擇，不能默認穩定相容。
2. 根據實際套件格式決定可重現安裝與完整性驗證方式，記錄版本、來源與驗證資料；不直接把「HTTPS 或匯入成功」當作完整供應鏈驗證。
3. 設計單次更新互斥與清楚的切換狀態，處理兩個更新程序並行、更新時 App 正在執行，以及備份與切換之間遭中斷的行為。
4. 新套件先安裝與驗證，完成後才切換。原有套件在新版本尚未確認可用前須保留；恢復失敗要明確回報並保留可人工恢復的資料。
5. 測試不得真的向使用者 runtime 安裝套件；將 pip、檔案搬移與中斷點設成可注入行為，在隔離目錄驗證。

**必要測試：** pip 失敗、匯入失敗、驗證失敗、備份失敗、切換失敗、中斷後重啟、恢復失敗、並行更新及殘留暫存的安全清理。

**完成條件：** 不啟用半成品；失敗後仍可使用原版本或依明確步驟恢復；版本可追溯且備份不被無條件刪除。版本策略若仍待決定，保持未完成。

## 05．診斷遮蔽與資源限制

**候選修改位置：** `gui.py` 的 `handle()`、`start()`、事件佇列與讀取執行緒，`core.py` 的 Logger、進度與 `run_process()`；必要時新增 `tests/test_diagnostics.py`。

1. 以合成測試資料盤點第三方錯誤、stderr、URL 查詢參數、本機路徑可能出現的敏感內容；定義應保留與應遮蔽的資訊，集中處理後再寫檔。
2. 對超長診斷與事件設定明確上限及截斷標記，不把單筆大訊息寫入後才檢查檔案大小。
3. 為事件佇列、子程序輸出及工作時限選擇合理上限與錯誤行為。進度可合併，終止與結果事件不可被隨意丟棄；同時排空 stdout／stderr，避免限制措施造成死鎖。
4. 檢查磁碟空間與容量限制如何中止工作及回報；先以實際下載需求決定數值，不在計畫中虛構通用安全上限。
5. 日誌無法寫入或輪替失敗不應使 GUI 永久鎖定，也不能靜默掩蓋下載結果。

**必要測試：** 合成 token／帶憑證網址、長訊息、大量進度、佇列滿載、外部工具連續輸出、日誌失敗與逾時後的程序回收。

**完成條件：** 測試中的敏感值不落盤；上限有依據，超限行為可預期且不死鎖，結果事件與錯誤仍能到達 GUI。

## 06．下載與後續網路邊界

**候選修改位置：** `core.py` 的 `validate_url()`、`extract()`、`download()`、`ydl_options()` 及下載測試。

1. 追蹤網址正規化後實際傳給所有 yt-dlp 呼叫的值，確認下載入口不繞過相同限制。
2. 針對實際安裝的 yt-dlp／EJS 版本查官方資料與必要原始碼，確認後續請求、重新導向、代理及解題元件的行為，附來源與查證日期。
3. 建立非預期目的地與重新導向的可控測試。是否採目的地限制應依 YouTube／CDN 實際需求決定；不能只允許單一主機就宣稱完成，亦不能直接封鎖所有 CDN 導致合法下載失效。
4. 測試中繼資料變動、消失的格式、重複或未知選項、播放清單、進行中直播、無法搭配音訊及損壞輸出。
5. 確認每個成功檔案都經串流驗證，失敗項目不回報完成，部分成功保留已完成檔案並讓使用者看懂結果。

**必要測試：** 網址偽裝與非 HTTP(S)、畸形中繼資料、路徑逸出、格式更新、網路／HTTP 錯誤及部分成功。需要真網路的部分另列至 08，不以替身結果取代。

**完成條件：** 所有下載呼叫使用受控輸入，後續網路邊界有證據與對策；未確認部分明確列出，不以入口驗證推定安全。

## 07．GUI 實機操作與錯誤恢復

**候選修改位置：** `gui.py`、`tests/test_edit_shortcuts.py`、`tests/test_scroll.py`，以及必要的工作狀態測試。

1. 在實際 macOS 視窗測試中文／英文輸入法的 Command+A/C/V/X、右鍵選單、Enter、網址貼上與資料夾選擇。
2. 測試格式很多時清單內的滑鼠／觸控板捲動與兩方向；指標在清單外或清單未滿時不應誤捲動。
3. 測試讀取後更改網址、未勾選、重複點擊、背景程序異常退出、部分失敗與再次重試。每個終止路徑都須恢復可操作狀態。
4. 驗證目前工作中不允許正常關閉的提示；本輪不自動新增取消功能，若使用者要求取消，需另設計程序樹與清理後再實作。
5. 檢查三欄在最小尺寸、Retina 的文字與圖示，確認柴犬 idle／working／done／error 及完成動畫不遮擋資訊。

**必要測試：** 邏輯回歸測試加實機操作紀錄；只執行 Mock 測試不能勾選人工項目。截圖不得含使用者敏感資料。

**完成條件：** 實機檢查表逐項記錄，無卡死、重複啟動下載或錯誤成功顯示；只測過的環境列為已驗證。

## 08．真實 YouTube 下載驗收

**前提：** 受影響的安全測試通過，具有可用網路與使用者有權存檔的公開影片；輸出使用測試專用資料夾。

1. 記錄日期、程式檔案版本、Python／yt-dlp／EJS／工具版本與可公開的測試影片識別。
2. 驗證單支影片格式讀取、純音訊、需合併的影片與多選下載，至少各一次。
3. 用 ffprobe 檢查輸出必要串流、實際播放並記錄結果；不要把副檔名或非零檔案大小當成有效影音。
4. 檢查已存在同名檔案的內容仍不變，並確認進度、合併、驗證、部分失敗狀態與實際輸出一致。
5. 以可控方式驗證網路失敗與重試；403 未自然發生時可用替身測試錯誤分派，但須標明未重現真實 403。

**完成條件：** 真實格式讀取與下載有輸出及播放證據；網路不可用時保留此步未完成，不為通過而切換到未授權來源或忽略 TLS 驗證。

## 09．獨立 App／DMG 封裝與安裝

**候選修改位置：** `ShibaStudio.spec`、`scripts/build_macos.py`、`resources/entitlements.plist`、`licenses/`、`README.md`。工具僅放於專案內預定位置。

1. 依實際目標確認 macOS 最低版本與 CPU 架構；現有 macOS 26／arm64 是候選值，Intel 與其他版本不能順帶宣稱支援。
2. 準備可信、可再散佈的 FFmpeg／ffprobe／Deno 及動態相依，記錄來源、版本、雜湊、編譯與授權資料；授權現況查官方來源，不沿用歷史推定。
3. 驗證建置前檢查：模組、真實 Tk 初始化、工具架構、來源與授權資料內容。不能建立空 `TOOLS_REVIEWED.json` 跳過。
4. 檢查建置是否覆寫既有 App、manifest 或輸出目錄；現行腳本含 PyInstaller `--noconfirm --clean`，先確認輸出位置與保留策略，不直接重跑覆蓋舊成品。此為需檢查的操作風險，不是已證實資料損失。
5. 用選定開發環境執行建置；檢查 bundle 內的 Python、Tk、套件、素材、工具及動態連結，不以指向開發機的 wrapper／符號連結充當獨立工具。
6. 在乾淨 macOS 使用者／測試環境掛載 DMG、拖曳安裝、退出 DMG，再從安裝位置啟動及下載；不得以開發機 PYTHONPATH 或 Homebrew 補足缺件。

**必要測試：** 缺工具失敗、缺資源、無外部 Python／Homebrew 環境、含空白與中文安裝位置、安裝後輸出與日誌位置。無法測試的環境列為阻擋。

**完成條件：** App 可獨立啟動與完成下載，DMG 安裝流程實測成功，依賴與成品可追溯。未簽署或未公證的測試成品須明確標示，不稱正式發佈版。

## 10．簽署、公證及對外發佈驗收

**前提：** 09 的成品驗收證據齊全；使用者已授權憑證使用、公證提交與相應發佈操作。不得索取或把憑證密碼寫入檔案與日誌。

1. 查證當時 Apple 官方簽署／公證要求，記錄來源；確認實際 Developer ID 與 keychain profile，不使用範例身分。
2. 驗證實際 entitlements 的必要性，依實際工具與套件測試結果決定，不為求啟動任意擴大權限。
3. 以已配置的授權身分簽署 App，執行簽署驗證、公證提交、票據附加與 Gatekeeper 評估；App 與 DMG 的結果分別記錄。
4. 檢查 `build_macos.py` 的成品狀態與命名是否依真正公證結果標示；不能只看提供參數或成功建立檔案。
5. 對準備交付的最終檔案記錄版本、SHA-256、工具與套件版本、支援環境、已知限制、安裝與恢復說明。簽署公證後須對最終成品重新計算雜湊。
6. 在對應下載／安裝情境驗證最終成品；公開上傳或發佈前，依既有明確授權執行，不把本計畫視為發佈許可。

**完成條件：** 簽署、公證、安裝與下載各自有實際結果；只有通過項目可標記完成。缺憑證或設備時交付測試成品與具體阻擋，不繞過保護或假稱已公證。
